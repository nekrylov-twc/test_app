# test_app

Тестовое приложение «фронтенд + бэкенд» в одном репозитории для проверки preview-стендов
pull request в App Platform Timeweb Cloud.

```
backend/   Node.js + Express, API и заметки в памяти
frontend/  React + Vite, статическая сборка в dist/
```

## Что показывает страница

- **Метку сборки** крупно в шапке и цвет шапки — из `frontend/src/version.js`. Поменяли в PR, значит
  превью видно издалека.
- **Frontend**: время сборки, git-ветку и коммит (если `.git` доступен при сборке) и переменные окружения
  сборки, похожие на ветку, коммит, PR или деплой (значения с `TOKEN`, `SECRET`, `KEY`, `PASSWORD` в имени скрыты).
- **Backend**: метку из `backend/src/version.js`, случайный id инстанса (меняется при каждом запуске), аптайм,
  счётчик запросов и такие же переменные окружения рантайма.
- **Предупреждение**, если метки фронтенда и бэкенда расходятся (превью фронтенда смотрит в прод-бэкенд),
  и красную плашку, если расходится `apiContract`.
- **Заметки** в памяти бэкенда: добавьте заметку на превью и проверьте, что на проде её нет.
- **Заголовки ответа** `X-Robots-Tag`, `Cache-Control`, `Server` для самой страницы и для бэкенда — проверка, что
  превью закрыто от индексации.

## Настройка в App Platform

### Backend

| Поле | Значение |
|---|---|
| Тип | Backend, Node.js 18+ |
| Директория | `backend` |
| Команда сборки | `npm install` |
| Команда запуска | `npm start` |
| Порт | `3000` (или любой из переменной `PORT`) |

Эндпоинты: `GET /api/health`, `GET /api/info`, `GET|POST /api/notes`, `DELETE /api/notes/:id`.
CORS открыт для всех доменов.

### Frontend

| Поле | Значение |
|---|---|
| Тип | Frontend, React (Vite) |
| Директория | `frontend` |
| Команда сборки | `npm install && npm run build` |
| Директория сборки | `dist` |
| Переменная окружения | `VITE_API_URL=https://<техдомен-бэкенда>` |

`VITE_API_URL` вшивается в бандл при сборке, поэтому превью фронтенда по умолчанию ходит в тот бэкенд,
что записан в переменной. Чтобы направить его в превью бэкенда без пересборки, откройте
`https://<превью-фронтенда>/?api=https://<превью-бэкенда>` — адрес запомнится в браузере, сбросить
можно кнопкой на странице.

## Сценарий проверки превью

1. Задеплоить `main` как два приложения: backend и frontend.
2. Создать ветку, поменять в ней `label` (и `accent` у фронтенда) в обоих `version.js`, открыть PR.
3. Проверить: появились ли стенды, пришла ли ссылка в PR, какая метка на превью, куда смотрит превью
   фронтенда, видны ли переменные с веткой/коммитом/номером PR, есть ли `X-Robots-Tag`.
4. Запушить ещё коммит в PR — превью должно пересобраться, id инстанса бэкенда смениться.
5. Закрыть или смёржить PR — стенды должны исчезнуть.

Для проверки расхождения контрактов поднимите `apiContract` только в одном из `version.js`.

## Локальный запуск

```bash
npm --prefix backend install
npm --prefix backend start
```

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

Vite проксирует `/api` на `http://localhost:3000`, фронтенд открывается на `http://localhost:5173`.
